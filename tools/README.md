# Инструменты разработки

[Назад к проекту](../README.md)

Команды ниже выполняются из корня репозитория. Сборку и нативные UI-проверки запускайте Windows Python.

## Ресурсы и сборка

```powershell
python tools\prepare_assets.py
python tools\build_client.py
```

Первая команда создаёт копии ресурсов и адаптированные страницы в `client/frontend/`, обновляет `assets/manifest.json`. Вторая уже включает подготовку ресурсов и собирает `dist/Mogobe/`. Исходные ресурсы в `assets/` и готовые адаптеры нужны в Git; копии frontend и результаты сборки игнорируются.

После изменения `tools/host/MogobeHost.as` пересоберите адаптер с Java 17 и JPEXS 26.3:

```powershell
python tools\build_host.py --java path\to\java.exe --ffdec path\to\ffdec.jar
python tools\build_client.py
```

`build_loading_stub.py` создаёт служебный класс загрузочного экрана; `extract_original_preloader.py` извлекает оригинальную заставку; `build_map_additions.py` извлекает исходную кнопку и остров Бумагленда. Эти шаги не нужны при обычной сборке. `prepare_icon.py` требует Pillow; `verify_exe_icon.py` — Pillow и pefile.

После замены SWF комнаты геометрия извлекается отдельно, с Pillow, Java и JPEXS:

```powershell
python tools\export_room_geometry.py --room FearCaveGate --java path\to\java.exe --ffdec path\to\ffdec.jar
python tools\prepare_room_navigation.py --room FearCaveGate --render-dir tools\exports\room-geometry\renders
```

Без `--room` обрабатываются все комнаты. Однокомнатное обновление сохраняет остальные записи и ID. После импорта проверьте маршруты, метаданные источника и отчёт `assets/original/room-import.json`.

## Индекс графики предметов

`python tools/audit_shop_assets.py --archive-root "PATH_TO_GAME_ARCHIVE"` читает `Ru/Clothes.zip`, а при наличии также `He/Items.zip` и `Br/BigItems BR.zip`, без распаковки. Результат — `assets/catalogs/shop-assets.json`: ID и доступные представления русских предметов, контрольные суммы архивов, сведения об окне магазина и формат протокола. `--output` позволяет выбрать другой путь. Скрипт нужен для исследования архива и не входит в обычную сборку; исторические цены и ассортимент из графики не выводятся.

## Проверки настоящего окна Windows

Нужны Python с `httpx` и Pillow и тестовая сборка:

```powershell
python tools\build_client.py --ui-test
python tools\verify_client.py
python tools\verify_client.py --suite spawns
```

| Сценарий `--suite` | Что проверяется |
| --- | --- |
| `world-shops` | Один игрок: подход к 14 исходным точкам, ровно одно окно без промежуточного пустого, покупка на второй странице, живая смена привязки и категорий инвентаря |
| `shops` | Один игрок: покупки и опыт, `/give`, оригинальный попап, числовой уровень, живой значок администратора, профиль и карта |
| `admin-catalog` | Один игрок: три административных каталога из 2 456 ID, перелистывание, превью бумаг/дома и анимации без отдельной иконки |
| `admin` | Единая админка в отдельном Edge: обзор, вход, могоби, права, балансы, предпросмотр, магазины и награды |
| `commands` | Два могоби: справка по правам, выдача себе и по нику, публичные/административные магазины и объявления между локациями |
| `world` (по умолчанию) | Один могоби: Новоград, ходьба, `/exit`, повторный вход |
| `spawns` | Стороны перехода, ворота страха, F5 из двух комнат |
| `room-links` | Терем, выставка, дерево, пещера и корабль |
| `map-timing`, `map-ui` | Первый кадр карты, Бумагленд, магазины, бассейн |
| `rooms`, `rooms-all` | Карта и переходы с двумя игроками; дополнительно все 50 комнат |
| `layout` | Профили без мерцания, подсказки, чат и расположение элементов |
| `presence` | Онлайн друзей, экран сервера и `/online` |
| `friends-ui`, `friends` | Интерфейс друзей, мгновенный мут и F5; либо только друзья и мут |
| `social` | Эмоции, магия на другом игроке, друзья и мут |
| `profiles`, `multiplayer` | Карточки; либо два игрока, чат и запрет второго входа |
| `registration` | Полная регистрация и сообщения об ошибках |
| `accounts` | Долгая проверка шести сохранённых могоби |
| `all` | Все сценарии, только при явной необходимости |

Выбирайте проверку по изменению. Обычная сборка не запускает UI-тесты. Сценарии используют временные SQLite и профили, отчёты и снимки создаются в `verification/<suite>/`. Мост управления окном есть только в EXE с тегом `uitest`.

Запускайте UI-сценарии последовательно, без других действий Windows, отнимающих фокус. Кнопка входа оригинального SWF имеет задержку 5 секунд: проверка должна ждать её готовности.

`import_shop_graphics.py --archive-root "PATH_TO_GAME_ARCHIVE"` — разовый импорт оригиналов из `Ru/Clothes.zip` и окна `Ru/Popups/p_33.swf`. Обновляет `sources.json` и метаданные графики. Обычная сборка и запуск используют уже сохранённые файлы в репозитории. При `prepare_assets.py` файлы `Swf/Items/` попадают в манифест, но не копируются в frontend: их обслуживает сервер.

Для `admin` тестовому Python дополнительно нужен пакет `websockets`: проверка управляет отдельным Edge через CDP, не открывая админку внутри игры. Используются временные БД и профиль Edge.

`verify_client.py --suite wardrobe` — два тестовых могоби: надевание через оригинальный инвентарь, показ одежды у обоих игроков, стойка/ходьба, сохранение после F5, снятие и настоящее фото в буфере Windows. Использует временную базу и заменяет содержимое буфера тестовым портретом.

Для повторной подготовки анимаций с Java/JPEXS: скомпилируйте `MergeItemAnimations.java` с `ffdec.jar` в classpath; запустите `MergeItemAnimations <assets/original/Swf/Items> <временная папка>`, затем `python tools/build_item_animations.py <временная папка>`. Готовые SWF и происхождение уже включены в `assets/compat/item-animations/`; для обычного запуска и сборки Java не нужна.

`index_walking_previews.py` находит первый видимый кадр и измеряет границы 108 анимаций без отдельного Display. Готовые параметры — в `assets/catalogs/shop-graphics.json`; оригинальные SWF не меняются.

`python tools/index_shop_points.py` повторно извлекает видимые области торговли из исходных SWF комнат в `server/src/shops/points.json`. Оригиналы и назначения магазинов в SQLite не меняются. Для проверки без записи рабочего индекса используйте `--output путь.json`.

Для повтора отдельных комнат: `python tools/verify_shops.py --world-points --point-room vugovo --point-room bumagsstore`. Покупка и живая смена привязки проверяются при таком запуске также.
