# Работа с репозиторием

## Назначение и структура

Восстанавливаем русскую Mogobe с оригинальными SWF. Windows-клиент: Go + Wails + WebView2 + локальный Ruffle. Сервер: FastAPI + SQLite. Начните с `README.md` и документации нужного раздела.

- `client/`: Go-оболочка; `frontend/` — наш HTML/JS; `internal/` — конфиг, DPAPI-хранилище аккаунтов и шлюз.
- `server/src/auth/`, `profiles/`, `world/`: предметные модули; `legacy/` — адаптер оригинального XML/SmartFox-протокола.
- `assets/original/`: найденные оригиналы; `assets/compat/`: отдельные адаптеры и извлечённые фрагменты; `assets/ruffle/`: закреплённый runtime с лицензиями.
- `tools/host/MogobeHost.as`: исходник SWF-адаптера; `tools/`: сборка, извлечение геометрии и проверки.

## Принципы изменений

- Используйте оригинальные интерфейсы, персонажей, анимации и шрифты. Не перерисовывайте их и не меняйте стек без запроса пользователя.
- Не правьте байты оригиналов для исправления интерфейса. Исправления делайте в адаптере; производные ресурсы храните в `assets/compat/`.
- При запрошенной замене оригинала сохраняйте полезный прежний вариант в `Rooms/Preserved/`, обновляйте `sources.json`, контрольные суммы и соответствующую геометрию. Используйте исходные или понятные имена вместо `p_7.swf` и подобных номеров.
- Источник ресурсов — `assets/`. Копии SWF, runtime, HTML регистрации и картинок в `client/frontend/` генерируются через `tools/prepare_assets.py`; не редактируйте их вручную и не добавляйте в Git.
- Обычная сборка должна работать из клона без Downloads, старого прототипа, личных путей и внешнего архива игры. Java/JPEXS нужны только для изменения адаптера или извлечения геометрии.
- Сохраняйте стабильные ID комнат. Не путайте номера исходных `mcEntryPoint_*` с ID серверных комнат. При изменении SWF или позиции прохода синхронизируйте серверную и клиентскую геометрию.
- Следуйте принятой предметной структуре FastAPI: `router`, `schemas`, `models`, `service`, `dependencies`; общие настройки и БД отдельно. Ориентир: [fastapi-best-practices-ru](https://github.com/firocore/fastapi-best-practices-ru).

## Поведение, которое нужно сохранять

- Обычный вход и вход после `/exit` — Новоград. F5 — текущая комната, одноразовое намерение в памяти на 60 секунд, привязанное к сессии. Координаты в SQLite не сохраняются.
- Появление случайное на основной маске ходьбы, с отступом от триггеров и других игроков; переход пешком — возле обратного прохода. Неизвестные маршруты не выдавайте за подтверждённые.
- Один аккаунт имеет только одно активное игровое подключение. Не отзывайте сессию первого игрока при отклонённой попытке повторного входа.
- Личный мут фильтрует чат, эмоции и магию только для включившего его игрока. Магия должна работать и на другом могоби в той же комнате.
- Список могоби сохраняет регистр имён, порядок слева направо и до шести записей. Токены защищены DPAPI в Go; пароли не сохраняются. Не передавайте токены в JS/SWF и не логируйте пароли, query string или тела авторизации.
- Социальные данные обновляются по событиям; не возвращайте постоянный опрос `/api/social/me`. Оригинальная загрузка закрывается только после готовности комнаты, панели и аватара.
- Игровое состояние и блокировки аккаунтов общие для одного процесса FastAPI. Используйте один worker до появления общего хранилища и межпроцессной рассылки.

## Проверки и сборка

Сервер, из `server/`:

```text
uv sync --locked
uv run pytest -q
uv run ruff check .
```

Клиент, на Windows из `client/`: `go test ./...`. Сборка из корня: `python tools/build_client.py`; подготовка ресурсов уже включена. После правки `MogobeHost.as` сначала выполните `tools/build_host.py` с Java/JPEXS, затем пересоберите EXE.

Выбирайте UI-сценарий по изменению: сначала `python tools/build_client.py --ui-test`, затем `python tools/verify_client.py --suite <имя>`. Список — в `tools/README.md`.

- По умолчанию проверка короткая, с одним могоби. Не запускайте шесть аккаунтов или `--suite all` для обычной правки; `accounts` нужен при изменении списка или сохранения авторизации.
- Нативные UI-проверки запускайте последовательно. Не открывайте другие окна и не запускайте параллельно команды Windows, которые могут отобрать фокус.
- У оригинальной кнопки входа задержка 5 секунд. Ждите её готовности; при выборе цвета проверяйте настоящую область клика.
- Тесты используют отдельную временную БД и профиль. Не удаляйте пользовательскую SQLite, сессии, `.env` или настройки клиента при уборке.
- Не добавляйте в Git `dist/`, отчёты `verification/`, декомпиляции `tools/exports/`, кэши, `.venv`, ключи туннелей и генерируемые копии ресурсов. Сохраняйте `uv.lock`, `go.sum`, исходные SWF, готовый адаптер и лицензии Ruffle.
- Не публикуйте репозиторий, не создавайте коммит и не отправляйте изменения без соответствующего запроса пользователя. В результате укажите изменённое поведение, выполненные проверки и оставшиеся ограничения.
