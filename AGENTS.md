# Работа с репозиторием

## Назначение и структура

Восстанавливаем русскую Mogobe с оригинальными SWF. Windows-клиент: Go + Wails + WebView2 + локальный Ruffle. Сервер: FastAPI + SQLite. Начните с `README.md` и документации нужного раздела.

- `client/`: Go-оболочка; `frontend/` — наш HTML/JS; `internal/` — конфиг, DPAPI-хранилище аккаунтов и шлюз.
- `server/src/auth/`, `profiles/`, `world/`, `shops/`, `inventory/`, `admin/`: предметные модули; `legacy/` — адаптер оригинального XML/SmartFox-протокола.
- `assets/original/`: найденные оригиналы; `assets/compat/`: отдельные адаптеры и извлечённые фрагменты; `assets/ruffle/`: закреплённый runtime с лицензиями.
- `tools/host/MogobeHost.as`: исходник SWF-адаптера; `tools/`: сборка, извлечение геометрии и проверки.

## Принципы изменений

- Используйте оригинальные интерфейсы, персонажей, анимации и шрифты. Не перерисовывайте их и не меняйте стек без запроса пользователя.
- Не правьте байты оригиналов для исправления интерфейса. Исправления делайте в адаптере; производные ресурсы храните в `assets/compat/`.
- При запрошенной замене оригинала сохраняйте полезный прежний вариант в `Rooms/Preserved/`, обновляйте `sources.json`, контрольные суммы и соответствующую геометрию. Используйте исходные или понятные имена вместо `p_7.swf` и подобных номеров.
- Источник ресурсов — `assets/`. Копии SWF, runtime, HTML регистрации и картинок в `client/frontend/` генерируются через `tools/prepare_assets.py`; не редактируйте их вручную и не добавляйте в Git.
- Обычная сборка должна работать из клона без Downloads, старого прототипа, личных путей и внешнего архива игры. Java/JPEXS нужны только для изменения адаптера или извлечения геометрии.
- Сохраняйте стабильные ID комнат. Не путайте номера исходных `mcEntryPoint_*` с ID серверных комнат. При изменении SWF или позиции прохода синхронизируйте серверную и клиентскую геометрию.
- Следуйте принятой предметной структуре FastAPI: `router`, `schemas`, `models`, `service`, `dependencies`; общие настройки и БД отдельно. Ориентир: [fastapi-best-practices-ru](https://github.com/firocore/fastapi-best-practices-ru).

## Поведение, которое нужно сохранять

- Обычный вход и вход после `/exit` — Новоград. F5 — текущая комната, одноразовое намерение в памяти на 60 секунд, привязанное к сессии. Координаты в SQLite не сохраняются.
- Появление случайное на основной маске ходьбы, с отступом от триггеров и других игроков; переход пешком — возле обратного прохода. Неизвестные маршруты не выдавайте за подтверждённые.
- Один аккаунт имеет только одно активное игровое подключение. Не отзывайте сессию первого игрока при отклонённой попытке повторного входа.
- Единая админка сервера находится в `src/admin/`, открывается на `/admin` и запускается отдельным окном через `StartAdmin.bat`; не встраивайте её в игру и не проксируйте административные маршруты игровым Go-шлюзом. Магазины и предметы редактируются в SQLite без перезапуска; права администратора — `Account.is_admin`. Значок могокарты в профиле обозначает администратора, подписка не реализуется. Права, цену, остаток и баланс проверяйте сервером при каждой покупке. Опыт (`Account.experience`) начисляется в той же транзакции; исходные пороги уровней — в `profiles/progression.py`. `/give item ID [ник]`, `/give exp ЧИСЛО [ник]`, `/give coins ЧИСЛО [ник]` и `/alert текст` находятся в `src/admin/commands.py` и проверяют текущие права по SQLite; без ника выдача себе, с ником — указанному аккаунту, включая офлайн; опыт показывается через штатное событие `user__worldScoreChange`. Для оригинального профиля используйте публичные `popup.Data`, не обращайтесь к защищённым свойствам `Card.UserCardId` или `Card.user`. Данные профиля обновляйте при открытии и событиях, без постоянного серверного опроса. Вся графика предметов встроена в EXE: `tools/prepare_item_assets.py` создаёт `client/frontend/items/` из `assets/`, Go-шлюз обслуживает Display/InUse/Cats локально, включая локальный 404 без сетевого fallback. Сервер передаёт ID и игровые данные; графические API сохранены для отдельной web-админки. Генератор обёрток `src/shops/swf_graphics.py` использует только стандартную библиотеку Python. Новые серверные категории должны работать через локальные шаблоны `btnCatID` без пересборки; новая графика требует обновления клиента.
- Экипировку проверяет сервер по ID принадлежащей вещи; не доверяйте присланным typeId/pCat. Сохраняйте выбор в inventory_equipped и рассылайте items в комнату, включайте одежду в снимок при входе. Оригинальному ItemFactory нужны оба класса mlIconSItemID/mlIconWItemID в одной библиотеке; встраивайте готовые объединённые файлы assets/compat/item-animations как items/InUse, без дублирования исходных стоящих/идущих библиотек. Фото из профиля обрабатывайте локально; данные изображения не должны уходить на игровой сервер.
- Личный мут фильтрует чат, эмоции и магию только для включившего его игрока. Магия должна работать и на другом могоби в той же комнате.
- Список могоби сохраняет регистр имён, порядок слева направо и до шести записей. Большой и маленькие портреты авторизации используют оригинальные LoginAvatar и itemsIdList. Локальный снимок item_ids обновляется только по серверным данным (собственные joinOK/uVarsUpdate или однократное обновление профилей перед показом входа); сохраняйте его для имён без запомненной сессии, не используйте как доказательство владения. Ошибки связи и истёкшие сессии не должны стирать одежду, успешный пустой список должен её снимать. Старые DPAPI-файлы версии 1 остаются читаемыми. Для этой функции используйте короткий сценарий login-outfits с двумя могоби, без полного теста шести аккаунтов. Токены защищены DPAPI в Go; пароли не сохраняются. Не передавайте токены в JS/SWF и не логируйте пароли, query string или тела авторизации.
- Социальные данные обновляются по событиям; не возвращайте постоянный опрос `/api/social/me`. Оригинальная загрузка закрывается только после готовности комнаты, панели и аватара.
- Игровое состояние и блокировки аккаунтов общие для одного процесса FastAPI. Используйте один worker до появления общего хранилища и межпроцессной рассылки.

## Проверки и сборка

Сервер, из `server/`:

```text
uv sync --locked
uv run pytest -q
uv run ruff check .
```

Клиент, на Windows из `client/`: `go test ./...`. Сборка из корня: `python tools/build_client.py`; подготовка ресурсов уже включена. После правки `MogobeHost.as` сначала выполните `tools/build_host.py` с Java/JPEXS, затем пересоберите EXE.

Выбирайте UI-сценарий по изменению: сначала `python tools/build_client.py --ui-test`, затем `python tools/verify_client.py --suite <имя>`. Список — в `tools/README.md`.

- По умолчанию проверка короткая, с одним могоби. Не запускайте шесть аккаунтов или `--suite all` для обычной правки; `accounts` нужен при изменении списка или сохранения авторизации.
- Нативные UI-проверки запускайте последовательно. Не открывайте другие окна и не запускайте параллельно команды Windows, которые могут отобрать фокус.
- У оригинальной кнопки входа задержка 5 секунд. Ждите её готовности; при выборе цвета проверяйте настоящую область клика.
- Тесты используют отдельную временную БД и профиль. Не удаляйте пользовательскую SQLite, сессии, `.env` или настройки клиента при уборке.
- Не добавляйте в Git `dist/`, отчёты `verification/`, декомпиляции `tools/exports/`, кэши, `.venv`, ключи туннелей и генерируемые копии ресурсов. Сохраняйте `uv.lock`, `go.sum`, исходные SWF, готовый адаптер и лицензии Ruffle.
- Не публикуйте репозиторий, не создавайте коммит и не отправляйте изменения без соответствующего запроса пользователя. В результате укажите изменённое поведение, выполненные проверки и оставшиеся ограничения.

- `/room` и `/shop` доступны всем; `admin_only` конкретного магазина проверяется сервером. `/help` получает актуальный список из `/api/world/commands`, без фонового опроса. Глобальные `/alert` показывайте в оригинальном окне каждому игроку независимо от комнаты; очередь не должна перекрывать уже открытую справку/ошибку. При выдаче опыта анимация приходит получателю, а не отправителю.

- При старте FastAPI после миграций `src/admin/bootstrap.py` создаёт отсутствующий аккаунт admin/admin с правами и пополняет закрытые магазины admin1 (одежда), admin2 (бумаги) и admin3 (дом). Разметка в assets/catalogs/item-classification.json восстановлена по графике; не считайте пол бумаг и слоты с evidence=placement-anchor подтверждёнными серверными данными. При переносе старого числового каталога сохраняйте предложения и покупки; ручную разметку не перезаписывайте. Не сбрасывайте существующие пароли/права и правки каталога. Настройка MOGOBE_BOOTSTRAP_DEFAULTS=false нужна тестам с собственными фикстурами; начальная настройка проверяется отдельно.

- Точки магазинов извлекаются из исходных комнат и перечислены в `server/src/shops/points.json`; назначения редактируются в SQLite через `ShopPoint`. Не зашивайте ключ магазина в SWF: клиент получает доступные назначения при входе в комнату и по событиям. Стартовые 14 публичных магазинов из `assets/catalogs/world-shops.json` создавайте только при отсутствии ключа; удалённые оператором предложения и привязки не восстанавливайте. Подборки приблизительные, иллюстрации вики не доказывают исторические цены или ID. Изменение типа/слота вещи и категории предложения должно обновлять уже купленные вещи, сверять экипировку и уведомлять владельцев без переподключения.

- Магазины в мире открываются через штатный триггер после подхода персонажа. Не перехватывайте клики по прямоугольным границам магазина: исходные формы могут быть повёрнуты и иметь непрямоугольный контур. Подключайте привязки и в `rooms__getStoreData`, чтобы оригинальные окна не оставались пустыми. Покупка и изменение цены/остатка должны сохранять текущую категорию, страницу и выбранную вещь.
