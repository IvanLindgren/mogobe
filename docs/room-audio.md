# Музыка локаций

Сохранённые оригинальные MP3 встроены в клиент. Графика и звук для обычного запуска берутся из репозитория, без Downloads, внешнего архива и запросов аудио к игровому серверу.

| Локация | Исходный файл | Основание привязки |
| --- | --- | --- |
| Новоград (`novograd`) | `Novograd.mp3` | Имя файла соответствует локации |
| Отдыхаево (`summercamp`) | `otdyhaevo.mp3` | Имя файла соответствует русскому названию локации |
| Вход в лабиринт (`maze_entrance`) | `DukeMaze.mp3` | Временная привязка трека лабиринта к доступному входу; историческая точка воспроизведения не подтверждена |

Файлы находятся в `assets/original/Sound/Rooms/`, исходник — `Movies/` из пользовательского архива. Байты MP3 не менялись; происхождение и SHA-256 внесены в `assets/original/sources.json`.

## Поведение

Музыка запускается при входе в соответствующую комнату и повторяется штатным обработчиком. При переходе в другую комнату предыдущий фон плавно затихает. Оригинальная кнопка звука отключает одновременно музыку и звуковые эффекты; её состояние сохраняется при переходах внутри текущего игрового подключения. F5 заново подключает музыку текущей комнаты. После `/exit` проигрыватель мира уничтожается.

У оригинального `SoundManager` фон, загруженный при выключенном звуке, получает нулевую громкость канала. Адаптер замечает включение звука и повторно запускает этот фон через публичный API оригинального менеджера, иначе смена общего `SoundMixer` не делает канал слышимым. На время рыбалки фон комнаты приостанавливается; после закрытия оригинального экрана результата запускается заново.

## Как подключено

Сопоставления комнат и имён файлов находятся в `server/src/world/audio.json`. После изменения файла нужен перезапуск сервера. Сервер включает имя MP3 в штатную переменную комнаты `rbs` в пакете `joinOK`. Это настоящее имя `RoomTO.SFSVar_bgSound` оригинального клиента. `BaseRoom` добавляет путь `/Sound/Rooms/`, а `SoundManager` загружает и воспроизводит локальный файл. Новый интерфейс проигрывателя и отдельный фоновый опрос не добавлялись.

`tools/prepare_assets.py` копирует MP3 в генерируемую `client/frontend/Sound/`; Go встраивает их вместе с остальными ресурсами. При добавлении нового файла музыки требуется пересборка клиента. При изменении привязки уже встроенного файла достаточно перезапуска сервера.

## Остальные сохранённые звуки

В исходных SWF `Pool`, `Submarine`, `FearCave` и `SpaceshipBridge` есть встроенные звуковые потоки. Они оставлены в оригиналах; общий `SoundMixer` действует и на них. `FearCave` и `SpaceshipBridge` пока не подключены как обычные прогулочные комнаты.

Записи `party_dec_12.mp3` и `party_dec_12-2.mp3` остаются в пользовательском архиве как записи мероприятий. Подтверждённой текущей комнаты/ивента для них нет, поэтому они не назначены обычным локациям и не включены в сборку. Полного набора музыкальных файлов всех комнат пока нет.

## Проверка

`python tools/verify_client.py --suite room-audio` использует одного тестового могоби, отдельную SQLite и headless Edge с `--mute-audio`. Проверяются загрузка и декодирование оригинальных MP3, реальные вызовы WebAudio, смена комнат, mute/unmute при переходе, остановка фона в комнате без трека, работа рядом с встроенным звуком бассейна, рыбалка, настоящий `SOUND_COMPLETE` и штатный повтор, F5 и `/exit`. Файлы должны приходить из встроенных ресурсов клиента.

Для протокола и комплекта исходных файлов: `uv run pytest -q tests/test_rooms.py tests/test_world.py tests/test_minigames.py`. Отчёт UI-проверки находится в игнорируемой папке `verification/room-audio/`.
