# Сервер

[Назад к проекту](../README.md)

FastAPI, SQLAlchemy, aiosqlite и Alembic. Сервер реализует аккаунты и игровую логику для оригинального SWF-клиента.

## Запуск

Нужны Python 3.12+ и uv. Из этой папки:

```sh
uv sync --locked
uv run python run.py
```

Либо запустите `StartServer.bat` из корня на Windows. `run.py` создаёт каталог БД, применяет миграции и запускает сервер на `127.0.0.1:8000`. Документация REST — `/docs`, проверка доступности — `/api/health`.

```sh
uv run python run.py --host 0.0.0.0 --port 8000
uv run python run.py --migrate-only
```

`--log-level debug` меняет подробность логов. HTTP-журнал содержит метод, путь, статус и время ответа без параметров URL и тел запросов.

## Настройки

Скопируйте `.env.example` в `.env` при необходимости изменить значения. Локальные `.env` и база в Git не попадают.

| Переменная | По умолчанию |
| --- | --- |
| `MOGOBE_DATABASE_URL` | SQLite в `server/data/mogobe.sqlite3` |
| `MOGOBE_BOOTSTRAP_DEFAULTS` | `true`: аккаунт `admin` / `admin`, три административных и 14 публичных магазинов при запуске |
| `MOGOBE_SERVER_NAME` | `Локальный сервер` |
| `MOGOBE_SESSION_HOURS` | 24 |
| `MOGOBE_REMEMBERED_SESSION_DAYS` | 30 |
| `MOGOBE_REGISTRATION_MINUTES` | 30 |
| `MOGOBE_COOKIE_SECURE` | `false` для локального HTTP-шлюза клиента |
| `MOGOBE_LOGIN_LIMIT` | 12 попыток |
| `MOGOBE_LOGIN_WINDOW_SECONDS` | 300 секунд |

Переменные окружения имеют приоритет над `.env`. В поставляемом примере имя сервера задано как «Могоби». При прямом доступе из браузера по HTTPS можно включить secure cookies.

## Архитектура и данные

Структура следует [fastapi-best-practices-ru](https://github.com/firocore/fastapi-best-practices-ru): модули по предметным областям, протокольные адаптеры используют общие сервисы.

| Путь | Назначение |
| --- | --- |
| `src/auth/` | Регистрация, Argon2id, сессии, проверки доступа |
| `src/profiles/` | Карточки, дружба, заявки, лучшие друзья и личный мут |
| `src/admin/` | Общая админка, права, могоби, балансы и административные команды |
| `src/shops/` | Каталоги, покупки и графика предметов |
| `src/inventory/` | Надевание, снятие и сохранение одежды |
| `src/world/` | Каталог комнат, навигация, появление, присутствие и рассылка |
| `src/legacy/` | Старые XML-запросы и SmartFox 1.x поверх WebSocket |
| `src/config.py`, `src/database.py` | Настройки и асинхронная БД |
| `alembic/` | Версионируемые миграции |
| `tests/` | Изолированные проверки API и игрового протокола |

В SQLite сохраняются аккаунты, параметры регистрации, хеши сессий и социальные связи. Координаты и онлайн находятся только в памяти подключения. Один аккаунт может иметь одно активное игровое соединение; отклонённый повторный вход не завершает сессию первого игрока.

Обычный вход начинает игру в Новограде. Точки появления выбираются случайно на основной маске ходьбы вне триггеров, с учётом позиций игроков. F5 использует одноразовое намерение вернуться в текущую комнату: оно привязано к сессии и действует 60 секунд в памяти сервера. Обычный выход не сохраняет комнату.

Регистрация создаёт аккаунт на последнем этапе. Ники: 4–15 символов, латиница, кириллица с `Ёё`, цифры и `_`; сравнение имён не зависит от регистра. Почта, согласие с правилами и рассылка необязательны. Отправка писем и восстановление пароля не реализованы.

Принятая дружба, заявки, до четырёх лучших друзей и личный мут сохраняются между запусками. Мут фильтрует сообщения, эмоции и магию только для его владельца. Счётчик дней — полные сутки с регистрации в UTC. Социальные изменения доставляются событиями; постоянного HTTP-опроса `/api/social/me` нет.

## Удалённый доступ

Используйте обратный прокси с HTTPS и поддержкой WebSocket Upgrade для `/legacy/socket`. Нужны `/api/*` и `/legacy/*`; графика и Ruffle уже встроены в EXE. Сервер поддерживает только **один worker**: состояние комнат, блокировки аккаунтов и ограничение входов хранятся в одном процессе. Для нескольких процессов потребуется общее хранилище и рассылка событий.

`StartTunnel.bat` — необязательный запуск Cloudflare Tunnel с внешним конфигом `%USERPROFILE%\.cloudflared\mogobe.yml`. Настройте его ingress на `http://127.0.0.1:8000`; ключи и авторизация остаются вне репозитория. Скрипт использует cloudflared из PATH либо `%LOCALAPPDATA%\MogobeTools\cloudflared.exe`. Готовый туннель проект не создаёт.

## Проверки и миграции

```sh
uv run pytest -q
uv run ruff check .
uv run alembic upgrade head
```

Тесты используют отдельные базы. Не удаляйте рабочую SQLite для применения изменений: используйте миграции. Если запускаете `uvicorn src.main:app` напрямую, предварительно примените Alembic и оставьте один worker.

## Единая админка сервера

Полный список игровых команд и примеры — в [справочнике чат-команд](../docs/chat-commands.md).

При запуске после миграций сервер создаёт аккаунт **`admin`** с паролем **`admin`** и правами администратора, а также три закрытых магазина: `/shop admin1` (одежда), `/shop admin2` (бумаги), `/shop admin3` (интерьер дома). Настройка `MOGOBE_BOOTSTRAP_DEFAULTS=false` отключает эту начальную настройку. Существующий аккаунт с таким ником не меняется: пароль и права не сбрасываются. Редактирование предложений сохраняется при повторном запуске.

Чтобы назначить администратором другой игровой аккаунт, выполните из `server/`:

```sh
uv run python -m src.admin grant YOUR_USERNAME
# Снять права:
uv run python -m src.admin revoke YOUR_USERNAME
```

Запустите отдельное окно админки через `StartAdmin.bat` из корня репозитория и войдите этим аккаунтом. Сервер должен быть запущен. Для другого сервера: `StartAdmin.bat https://example.org`. Окно работает в Microsoft Edge со своим профилем; при отсутствии Edge открывается обычный браузер. Адрес для ручного открытия: `http://localhost:8000/admin`. В игровом клиенте админки нет, её маршруты заблокированы локальным шлюзом. Единая админка использует существующие аккаунты и отдельную сессию браузера. В игровом профиле администратора отображается оригинальный значок могокарты; подписка и её привилегии не реализуются.

1. Во вкладке «Предметы и графика» выберите ID, посмотрите исходную графику, задайте название, тип и категорию инвентаря, сохраните предмет. Тип выбирается вручную: папка `Clothes` содержит также бумаг и другие предметы, а наличие анимации не доказывает, что это одежда. Проверенные примеры: 100 — фиолетовая рубашка, 101 — красная рубашка; 1 и 2 — бумаги.
2. Создайте магазин с ключом, например `style`, названием и видом окна: одежда с примеркой или предметы с предпросмотром. Можно ограничить доступ администраторами, закрыть магазин или назначить ему исходные точки открытия в локациях.
3. Добавьте категории, выбрав оригинальную иконку из списка, и предложения: предмет, цену в монетах, остаток, порядок и флаг продажи. Пустой остаток означает отсутствие ограничения. Предмет может иметь разные цены в разных магазинах.
4. В игре отправьте `/shop style`. Изменения цен, названий предметов и ассортимента сразу действуют; открытые окна обновляются по WebSocket без перезапуска сервера или клиента. После смены вида окна закройте и откройте магазин заново.

Во вкладке «Могоби» есть поиск, список зарегистрированных персонажей, их опыт, числовой уровень, баланс и статус подключения. Там можно назначать и снимать права администратора; изменения действуют без переподключения. Права у последнего администратора через UI не снимаются, стартовый администратор `admin` создаётся автоматически, а другим аккаунтам права можно выдать серверной CLI-командой выше. Золотой значок могокарты в личном и чужом профиле обозначает администратора.

У каждого предложения есть поле «Опыт за покупку»: по умолчанию 10, допустимо 0–1 000 000. Опыт сохраняется вместе с монетами, остатком и вещью в одной транзакции. Неудачная или повторная покупка опыт не даёт. Начисление показывает оригинальную анимацию `mlWorldScoreSign`. Пороговые значения уровней сохранены из оригинального `UserExperience`: 1 000, 2 000, 4 000, 8 000, 16 000, 32 000, 64 000, 124 000, 256 000, 512 000 и 1 024 000. Цветовые названия в оригинальной подсказке профиля заменены подписями «Уровень: 1»–«Уровень: 12».

Административные команды выдают вещь, опыт или монеты. Ник получателя необязателен: без него выдача себе, с ним — указанному могоби, в том числе вне сети:

```text
/give item 100 [ник]
/give exp 500 [ник]
/give coins 100 [ник]
/alert Текст объявления всем игрокам
```

Предмет должен быть создан в каталоге админки; его можно выдать независимо от наличия предложения в магазине. Повторная выдача одной вещи отклоняется. Выдача вещи не списывает монеты и не даёт опыт. Для опыта принимаются целые числа от 1 до 1 000 000; монеты добавляются к балансу с общим пределом 1 000 000 000. Права проверяются по текущей записи SQLite при каждой команде. `/alert` показывает объявление всем игрокам во всех локациях, включая отправителя; доступно только администраторам. Очередь объявлений в клиенте ждёт закрытия текущего сообщения.

`/help` открывает панель на оригинальном оформлении с актуальными командами: `/room ключ`, `/shop ключ`, `/online`, `/exit`; административные `/give` и `/alert` видны при наличии прав. Сам список приходит из `/api/world/commands` только при открытии справки. `/room` и `/shop` доступны всем, но для магазинов с `admin_only` сервер проверяет права при открытии и покупке.

На вкладке «Монеты» можно установить тестовый баланс по нику. Новые аккаунты получают 0 монет; система заработка пока не реализована. Покупка проверяет текущие права, открытость магазина, доступность предмета, цену, остаток и баланс. Повторная покупка той же вещи запрещена. Списание, уменьшение остатка и выдача в инвентарь выполняются одной транзакцией. Скрытие товара не удаляет уже купленные вещи.

Настройки хранятся в SQLite и не кэшируются при старте. Обычные зарегистрированные аккаунты не получают права администратора; стартовый аккаунт `admin` создаётся отдельно. Закрытые и административные магазины проверяются и при открытии, и при каждой покупке. Основные API: `/api/shops/{key}`, `/api/shops/{key}/buy`, `/api/inventory`; управление — `/api/admin/*` (магазины — `/api/admin/shops/*`, предметы — `/api/admin/items`, могоби — `/api/admin/accounts`). Точная схема доступна в `/docs`.

Графика всех 6 133 файлов русского набора и оригинальный `Shop.swf` включены в репозиторий. Игровой клиент содержит все миниатюры, готовые анимации одежды и шаблоны иконок; сервер передаёт ID и игровые данные, не обслуживая загрузку графики из игры. Маршруты `/api/shop-assets/*` сохранены для отдельной web-админки и просмотра исходников. Серверу по-прежнему нужна папка `assets/` рядом с `server/`: она содержит индексы, классификацию, стартовые подборки и графику админки. Генератор совместимых обёрток `src/shops/swf_graphics.py` общий для сборки клиента и административных превью, не требует FastAPI для подготовки ресурсов. Для удалённого доступа проксируйте `/api/*` целиком. Внешние архивы, Java и JPEXS при запуске не нужны.

Экипировка хранится в `inventory_equipped` (`src/inventory/`), отдельно от временной позиции в комнате. Надевание проверяет владение, тип вещи и наличие обеих анимаций; вещь заменяет прежнюю в своём `inventory_category` (исходный `pCat`). Для одежды назначайте настоящую категорию: например, 4 — верх, 1 — низ, 3/7 — головной убор, 11 — обувь, 18/19 — очки. Полный набор исходных групп указан в `assets/README.md`. Снятые вещи остаются собственностью могоби. API: `GET /api/inventory/equipped`, `POST /api/inventory/equip` и `/unequip` с `owned_item_id`; оригинальный SWF использует команды `user__setInUseItem`/`user__setNotInUseItem`. Сервер рассылает авторитетное состояние `items` в комнату, а при входе передаёт полный снимок.

Общий модуль администрирования — `src/admin/`: вход, права, могоби, балансы, обзор сервера и web-интерфейс. Управление ассортиментом остаётся в `src/shops/admin_router.py`. Панель открывается с обзора: онлайн, зарегистрированные могоби, администраторы, локации, магазины и предметы. Общая CLI-команда: `uv run python -m src.admin grant НИК`. Старые `StartShopAdmin.bat`, `/admin/shops` и CLI `src.shops.admin` перенаправляют на общую админку; прежние API сохранены для совместимости и скрыты из документации.

Административные каталоги заполняются кнопкой «Обновить три админ-магазина» или командой `uv run python -m src.shops.seed_admin` из `server/`. Всего 2 456 ID: `/shop admin1` — 1 958 записей одежды и украшений, `/shop admin2` — 190 бумаг и их предметов, `/shop admin3` — 308 объектов дома, транспорта и пазлов. Все три магазина доступны только администраторам. В новых предложениях цена и опыт — 0, остаток не ограничен.

Разметка лежит в `assets/catalogs/item-classification.json`: `family`, `category`, оригинальный `main_type`, слот `inventory_category`, способ определения `evidence`. Это восстановленная классификация по SWF и их координатам, а не найденный серверный каталог; названия условные, пол бумаг не восстановлен (тип 6 служит общей группой). Типы: 1 — одежда; 2 — дом; 3/4 — украшения; 6/7 — бумаги; 8 — корм; 9 — игрушки; 10 — зелья; 11 — обустройство бумаг; 12 — пазлы; 13/14 — транспорт и детали. Механики питомцев, дома и транспорта пока не подключены. Эти предметы сохраняются в инвентаре, но сервер запрещает надевать их как одежду. У 108 Walking-only ресурсов слот 0: предпросмотр доступен, для надевания не хватает полной анимации.

Импорт обновляет только нетронутую разметку старого импорта (`Предмет ID`, тип 0, слот 0). Предложения из прежних категорий `ID 0001–0200` и т. п. переносятся в соответствующий магазин с сохранением цены, опыта, остатка и доступности; пустые числовые категории удаляются. Существующие покупки, ручные описания и настройки сохраняются. Повторный импорт не дублирует записи. В админке у списка графики и предметов есть фильтр по трём разделам; любой тип и слот можно уточнить вручную.
`/shop admin1` использует оригинальный магазин одежды (`kind=clothing`) с примеркой на могоби. Покупки и экипировка проходят через ту же систему, что и в обычном магазине. Остальные административные магазины используют окно объектов.

## Точки магазинов и категории инвентаря

`src/shops/points.json` хранит 23 видимые исходные области торговли из SWF. Назначения хранятся в таблице `shop_point`; поле «Точки в локациях» в админке поддерживает несколько точек на магазин. Одна точка принадлежит одному магазину. `GET /api/shop-points?room=ключ` возвращает доступные точки с учётом прав и включённости; `POST /api/shop-points/{point_id}/open` проверяет фактическую комнату игрового подключения и выдаёт каталог.

14 стартовых подборок задаются в `assets/catalogs/world-shops.json`: `mall`, `sportstore`, `clothesstore`, `furniturestore`, `kingsroad`, `sunandsea`, `spa`, `skazkino`, `jewelrystore`, `foresttree`, `bumagsstore`, `bumagsfoodtoysstore`, `bumagspotionstore`, `vugovo`. Это тематические кандидаты, не найденный серверный ассортимент. Новые предложения стоят 10 монет и дают 10 опыта. Начальная настройка создаёт только отсутствующие магазины, не восстанавливает удалённые предложения и не меняет привязки существующих. Кнопка «Создать отсутствующие магазины локаций» вызывает `POST /api/admin/shop-defaults`.

`shop_category.inventory_category` — необязательный общий слот для одежды. При его изменении обновляются предметы категории; при переносе предложения применяется слот новой категории. Прямое изменение `Item.inventory_category` также действует на существующие покупки. `inventory/reclassification.py` переносит экипировку в свободный слот либо снимает вещь при конфликте/несовместимом типе. Владение и история покупок сохраняются; подключённым владельцам отправляется штатное событие обновления инвентаря и одежды.

Штатный `rooms__getStoreData` выбирает магазин по назначенной исходной точке возле позиции игрока. REST-открытие точки также требует подхода, а не только нахождения в той же комнате. Сервер проверяет координаты с небольшим допуском; клиент использует точный `hitTestPoint` оригинальной формы и штатное событие завершения ходьбы.

## Миниигры

Модуль `src/minigames/` содержит каталог, API, зависимости активного игрока и сохранение результатов. Миграции `e264minigames` и `e265minigameexp` добавляют `minigame_run` и начисленный опыт; они применяются штатным запуском `run.py`; существующая SQLite сохраняется. Результат и изменение кошелька фиксируются одной транзакцией. Досрочный выход сохраняет счёт и начисляет заработанное; смена комнаты и отключение отменяют текущую попытку. Повторный запрос завершения возвращает прежний результат без повторного начисления.

- `GET /api/minigames` — доступные игры.
- `POST /api/minigames/goldfishing/start` — новая попытка; требуется активное игровое подключение той же сессии.
- `POST /api/minigames/runs/{id}/finish` — `{ "score": 1234, "completed": true }`; при досрочном выходе `completed: false`; для отмены без награды `cancelled: true`.
- `GET /api/minigames/results` — последние 20 завершённых/отменённых попыток текущего могоби.

Курс задаётся в `src/minigames/catalog.py`: 1 монета и 1 единица опыта за 100 очков, максимум по 100 за попытку. Результат, монеты и опыт сохраняются одной транзакцией. Полный раунд имеет статус finished, досрочный — stopped, отмена — cancelled. Сервер ограничивает длительность и диапазон результата, проверяет владельца и однократность выплаты. Сам счёт пока сообщает SWF: полноценной серверной симуляции рыбалки и проверки каждого улова нет. Прямые старые `user__increaseCoins` и `user__getGiftItem` для этой игры не используются.
