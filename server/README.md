# Сервер

[Назад к проекту](../README.md)

FastAPI, SQLAlchemy, aiosqlite и Alembic. Сервер реализует аккаунты и игровую логику для оригинального SWF-клиента.

## Запуск

Нужны Python 3.12+ и uv. Из этой папки:

```sh
uv sync --locked
uv run python run.py
```

Либо запустите `StartServer.bat` из корня на Windows. `run.py` создаёт каталог БД, применяет миграции и запускает сервер на `127.0.0.1:8000`. Документация REST — `/docs`, проверка доступности — `/api/health`.

```sh
uv run python run.py --host 0.0.0.0 --port 8000
uv run python run.py --migrate-only
```

`--log-level debug` меняет подробность логов. HTTP-журнал содержит метод, путь, статус и время ответа без параметров URL и тел запросов.

## Настройки

Скопируйте `.env.example` в `.env` при необходимости изменить значения. Локальные `.env` и база в Git не попадают.

| Переменная | По умолчанию |
| --- | --- |
| `MOGOBE_DATABASE_URL` | SQLite в `server/data/mogobe.sqlite3` |
| `MOGOBE_SERVER_NAME` | `Локальный сервер` |
| `MOGOBE_SESSION_HOURS` | 24 |
| `MOGOBE_REMEMBERED_SESSION_DAYS` | 30 |
| `MOGOBE_REGISTRATION_MINUTES` | 30 |
| `MOGOBE_COOKIE_SECURE` | `false` для локального HTTP-шлюза клиента |
| `MOGOBE_LOGIN_LIMIT` | 12 попыток |
| `MOGOBE_LOGIN_WINDOW_SECONDS` | 300 секунд |

Переменные окружения имеют приоритет над `.env`. В поставляемом примере имя сервера задано как «Могоби». При прямом доступе из браузера по HTTPS можно включить secure cookies.

## Архитектура и данные

Структура следует [fastapi-best-practices-ru](https://github.com/firocore/fastapi-best-practices-ru): модули по предметным областям, протокольные адаптеры используют общие сервисы.

| Путь | Назначение |
| --- | --- |
| `src/auth/` | Регистрация, Argon2id, сессии, проверки доступа |
| `src/profiles/` | Карточки, дружба, заявки, лучшие друзья и личный мут |
| `src/shops/` | Каталоги, права администратора, покупки, инвентарь и графика предметов |
| `src/world/` | Каталог комнат, навигация, появление, присутствие и рассылка |
| `src/legacy/` | Старые XML-запросы и SmartFox 1.x поверх WebSocket |
| `src/config.py`, `src/database.py` | Настройки и асинхронная БД |
| `alembic/` | Версионируемые миграции |
| `tests/` | Изолированные проверки API и игрового протокола |

В SQLite сохраняются аккаунты, параметры регистрации, хеши сессий и социальные связи. Координаты и онлайн находятся только в памяти подключения. Один аккаунт может иметь одно активное игровое соединение; отклонённый повторный вход не завершает сессию первого игрока.

Обычный вход начинает игру в Новограде. Точки появления выбираются случайно на основной маске ходьбы вне триггеров, с учётом позиций игроков. F5 использует одноразовое намерение вернуться в текущую комнату: оно привязано к сессии и действует 60 секунд в памяти сервера. Обычный выход не сохраняет комнату.

Регистрация создаёт аккаунт на последнем этапе. Ники: 4–15 символов, латиница, кириллица с `Ёё`, цифры и `_`; сравнение имён не зависит от регистра. Почта, согласие с правилами и рассылка необязательны. Отправка писем и восстановление пароля не реализованы.

Принятая дружба, заявки, до четырёх лучших друзей и личный мут сохраняются между запусками. Мут фильтрует сообщения, эмоции и магию только для его владельца. Счётчик дней — полные сутки с регистрации в UTC. Социальные изменения доставляются событиями; постоянного HTTP-опроса `/api/social/me` нет.

## Удалённый доступ

Используйте обратный прокси с HTTPS и поддержкой WebSocket Upgrade для `/legacy/socket`. Нужны `/api/*` и `/legacy/*`; графика и Ruffle уже встроены в EXE. Сервер поддерживает только **один worker**: состояние комнат, блокировки аккаунтов и ограничение входов хранятся в одном процессе. Для нескольких процессов потребуется общее хранилище и рассылка событий.

`StartTunnel.bat` — необязательный запуск Cloudflare Tunnel с внешним конфигом `%USERPROFILE%\.cloudflared\mogobe.yml`. Настройте его ingress на `http://127.0.0.1:8000`; ключи и авторизация остаются вне репозитория. Скрипт использует cloudflared из PATH либо `%LOCALAPPDATA%\MogobeTools\cloudflared.exe`. Готовый туннель проект не создаёт.

## Проверки и миграции

```sh
uv run pytest -q
uv run ruff check .
uv run alembic upgrade head
```

Тесты используют отдельные базы. Не удаляйте рабочую SQLite для применения изменений: используйте миграции. Если запускаете `uvicorn src.main:app` напрямую, предварительно примените Alembic и оставьте один worker.

## Магазины и временная админка

После обновления перезапустите сервер обычным способом: миграция добавит таблицы магазинов и признак администратора. Создайте обычный аккаунт в игре и выдайте ему права из папки `server/`:

```sh
uv run python -m src.shops.admin grant YOUR_USERNAME
# Снять права:
uv run python -m src.shops.admin revoke YOUR_USERNAME
```

Запустите отдельное окно админки через `StartShopAdmin.bat` из корня репозитория и войдите этим аккаунтом. Сервер должен быть запущен. Для другого сервера: `StartShopAdmin.bat https://example.org`. Окно работает в Microsoft Edge со своим профилем; при отсутствии Edge открывается обычный браузер. Адрес для ручного открытия: `http://localhost:8000/admin/shops`. В игровом клиенте админки нет, её маршруты заблокированы локальным шлюзом. Временная админка использует существующие аккаунты и отдельную сессию браузера. В игровом профиле администратора отображается оригинальный значок могокарты; подписка и её привилегии не реализуются.

1. Во вкладке «Предметы и графика» выберите ID, посмотрите исходную графику, задайте название, тип и категорию инвентаря, сохраните предмет. Тип выбирается вручную: папка `Clothes` содержит также бумаг и другие предметы, а наличие анимации не доказывает, что это одежда. Проверенные примеры: 100 — фиолетовая рубашка, 101 — красная рубашка; 1 и 2 — бумаги.
2. Создайте магазин с ключом, например `style`, названием и видом окна: одежда с примеркой или предметы с предпросмотром. Можно ограничить доступ администраторами, закрыть магазин или связать его с ключом комнаты.
3. Добавьте категории, выбрав оригинальную иконку из списка, и предложения: предмет, цену в монетах, остаток, порядок и флаг продажи. Пустой остаток означает отсутствие ограничения. Предмет может иметь разные цены в разных магазинах.
4. В игре отправьте `/shop style`. Изменения цен, названий предметов и ассортимента сразу действуют; открытые окна обновляются по WebSocket без перезапуска сервера или клиента. После смены вида окна закройте и откройте магазин заново.

Во вкладке «Могоби» есть поиск, список зарегистрированных персонажей, их опыт, числовой уровень, баланс и статус подключения. Там можно назначать и снимать права администратора; изменения действуют без переподключения. Права у последнего администратора через UI не снимаются, первый администратор по-прежнему назначается серверной CLI-командой выше. Золотой значок могокарты в личном и чужом профиле обозначает администратора.

У каждого предложения есть поле «Опыт за покупку»: по умолчанию 10, допустимо 0–1 000 000. Опыт сохраняется вместе с монетами, остатком и вещью в одной транзакции. Неудачная или повторная покупка опыт не даёт. Начисление показывает оригинальную анимацию `mlWorldScoreSign`. Пороговые значения уровней сохранены из оригинального `UserExperience`: 1 000, 2 000, 4 000, 8 000, 16 000, 32 000, 64 000, 124 000, 256 000, 512 000 и 1 024 000. Цветовые названия в оригинальной подсказке профиля заменены подписями «Уровень: 1»–«Уровень: 12».

Административные команды чата выдают предмет или опыт текущему могоби:

```text
/give item 100
/give exp 500
```

Предмет должен быть создан в каталоге админки; его можно выдать независимо от наличия предложения в магазине. Повторная выдача одной вещи отклоняется. Выдача вещи не списывает монеты и не даёт опыт. Для опыта принимаются целые числа от 1 до 1 000 000; права проверяются по текущей записи SQLite при каждой команде.

На вкладке «Монеты» можно установить тестовый баланс по нику. Новые аккаунты получают 0 монет; система заработка пока не реализована. Покупка проверяет текущие права, открытость магазина, доступность предмета, цену, остаток и баланс. Повторная покупка той же вещи запрещена. Списание, уменьшение остатка и выдача в инвентарь выполняются одной транзакцией. Скрытие товара не удаляет уже купленные вещи.

Настройки хранятся в SQLite и не кэшируются при старте. Права администратора не выдаются автоматически первому аккаунту. Закрытые и административные магазины проверяются и при открытии, и при каждой покупке. Основные API: `/api/shops/{key}`, `/api/shops/{key}/buy`, `/api/inventory`; редактирование — `/api/admin/shops/*`. Точная схема доступна в `/docs`.

Графика всех 6 133 файлов русского набора и оригинальный `Shop.swf` включены в репозиторий. Серверу нужна папка `assets/` рядом с `server/`: `/api/shop-assets/*` отдаёт графику с отдельными совместимыми обёртками. Сборка EXE не включает весь набор одежды: Go-шлюз запрашивает только нужные файлы с выбранного сервера. Для удалённого доступа проксируйте `/api/*` целиком. Внешние архивы, Java и JPEXS при запуске не нужны.
